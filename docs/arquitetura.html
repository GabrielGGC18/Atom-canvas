Arquitetura do ATOM Canvas

Canvas infinito local com terminais reais, notas e previews. Backend Python assíncrono fazendo ponte WebSocket ↔ PTY; frontend HTML/CSS/JS puro, sem build e sem CDN.

Python 3.10+aiohttpxterm.js WebSocketJS puro Windows · pywinptyLinux/macOS · ptyprocess 127.0.0.1 + token

1Visão geral

Aplicação local e de usuário único. O navegador mostra um plano infinito onde o usuário posiciona janelas livres, com pan, zoom e persistência automática.

Terminal term

Shell real (PowerShell no Windows, bash/zsh no Linux) via PTY, renderizado com xterm.js. Sessão sobrevive ao reload.

Nota note

Texto livre em <textarea>, salvo no layout.

Preview preview

Modos markdown (editor + render), image e browser (iframe com sandbox).

Princípios

PrincípioComo se aplica
Sem buildArquivos estáticos servidos direto; bibliotecas em static/vendor/ (funciona offline).
Backend mínimoUm processo aiohttp: servir arquivos, ponte WS ↔ PTY, ler/gravar JSON.
Estado no clienteO navegador é dono do estado do canvas; o servidor só persiste o JSON recebido.
Local-first e privadoBind em 127.0.0.1, token obrigatório, checagem de Origin.
MultiplataformaSó a classe Pty muda entre Windows e Linux/macOS; o resto é idêntico.

5.2 Abstração Pty

MétodoWindows (pywinpty)Linux/macOS (ptyprocess)
__init__spawn(SHELL, cwd, dimensions)spawn([SHELL], cwd, env, dimensions) com TERM=xterm-256color
read()read(4096) — bloqueante, roda em thread do PTY_READERS
write(d)envia teclas
resize(c, r)setwinsize(rows, cols)
alive() / kill()isalive() / terminate(force=True)
Cada terminal mantém uma thread presa em read(). Por isso existe o pool dedicado PTY_READERS: o executor padrão do asyncio (≈ cpus+4 threads) congelaria terminais novos depois de uns 12 abertos.

5.3 Sessões persistentes

@dataclass
class Session:
    sid: str      # = data.sessionId do frontend
    cwd: str
    pty: Pty
    output: str   # últimos 24.000 caracteres (replay)
    ws: object    # WebSocket anexado ou None
    task: object  # asyncio.Task do pump
    cols: int; rows: int

SESSIONS: dict[str, Session]   # em memória

Shell ≠ conexão

Fechar ou recarregar a aba desanexa o WebSocket; o shell continua rodando e bufferizando.

Reanexar

Mesmo sid → mesma sessão + replay de output.

Uma conexão por sessão

Nova conexão com o mesmo sid fecha a anterior.

Encerramento

on_shutdown → _kill_sessions: mata todos os PTYs e libera as threads. Ctrl+C sai na hora.

5.4 ws_term passo a passo

check_auth→ cwd válido? senão home→ ws.prepare()→ SESSIONS[sid] vivo? senão cria Pty + pump→ anexa WS, fecha anterior→ replay output→ resize→ loop: i → write · r → resize→ finally: desanexa (shell vive)

8Protocolos e API

11Sistema de coordenadas do canvas

#world recebe transform: translate(view.x, view.y) scale(view.s) com origem 0 0. Geometria dos nós (x, y, w, h) fica em coordenadas de mundo.

tela → mundo:   wx = (clientX - viewport.left - view.x) / view.s
mundo → tela:   cx = wx * view.s + view.x + viewport.left

zoom ancorado no cursor (ponto sob o mouse fica parado):
  ns     = clamp(view.s * fator, 0.15, 2.5)
  view.x = px - (px - view.x) * (ns / view.s)
  view.y = py - (py - view.y) * (ns / view.s)

Arrastar e redimensionar dividem o delta do mouse por view.s. Grade ligada: snapV() arredonda para múltiplos de 24. fitAll() enquadra o retângulo envolvente com escala máxima 1.2.

13Segurança

O ATOM Canvas expõe um shell completo pelo navegador. Quem acessar a URL com token controla a máquina com as permissões do seu usuário.
AmeaçaDefesa
Acesso pela redeBind fixo em 127.0.0.1
Adivinhar a URLToken aleatório de 128 bits em HTTP e WS
Site malicioso abrindo WS para localhost (CSWSH)Checagem de Origin (só 127.0.0.1/localhost na porta)
Path traversal no workspace_workspace_name: só [a-zA-Z0-9 _-], máx. 64
XSS via MarkdownEscape de & < > " ' antes da formatação
Dados pessoais no gitlayout.json e workspaces/ no .gitignore

Nunca use 0.0.0.0, port-forward ou túneis (ngrok etc.). Não compartilhe a URL com token.

15Limitações conhecidas

#LimitaçãoPossível melhoria
1Fechar janela, reiniciar (⟳) ou trocar workspace não mata o shell no servidor (sessão órfã até o servidor parar).DELETE /api/session/<sid> chamado por removeNode/restart.
2Sessões vivem só em RAM: reiniciar o servidor cria shells novos.tmux/screen no Linux como backend opcional.
3iframe com allow-scripts + allow-same-origin: se apontar para o próprio servidor, o sandbox perde efeito. Muitos sites bloqueiam iframe.Bloquear URLs de 127.0.0.1:<PORT>.
4Com zoom ≠ 100% a seleção com mouse no xterm pode desalinhar.Usar maximizar (sem scale).
5Duas abas no mesmo workspace sobrescrevem o JSON uma da outra.Versão/ETag no layout.
6Markdown simplificado (títulos, negrito, código inline, parágrafos).Parser completo vendorizado.
7Replay limitado a 24.000 caracteres.Configurável.
8Token na query string (fica no histórico do navegador).Cookie HttpOnly após primeira carga.

17Como estender

Novo tipo de janela

1) SIZES + ícone em P · 2) ramo em addNode · 3) initNovo(node) montando .body e chamando save() · 4) botão/menu · 5) CSS .node.novo.

Nova rota

Handler com check_auth(request), registrar em create_app(), chamar com ?token=${TOKEN}.

Novo atalho

Entrada no map do keydown + linha no modal #help.

Shell por janela

Aceitar shell na query do WS, validar contra lista permitida e passar para Pty.
